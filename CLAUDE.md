# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Public uptime tracker for PayHub, served at https://status.payhub.ly. It is an [Upptime](https://upptime.js.org/) deployment — there is no application code of our own. The repo is a config + assets + history store; GitHub Actions does all the work.

Operator runbook for incidents lives outside this repo at `docs/runbooks/status-page.md` in the main monorepo.

## How the pieces fit together

There is no local build. Everything happens in GitHub Actions:

- **`uptime.yml`** runs every 5 minutes, probes each `sites:` URL in `.upptimerc.yml`, and commits the result to `history/<slug>.yml` and `history/summary.json`. A probe failure auto-opens a GitHub issue (templates in `.github/ISSUE_TEMPLATE/`); recovery auto-closes it.
- **`graphs.yml`** / **`response-time.yml`** / **`summary.yml`** redraw the SVGs in `graphs/` and update the README badge table from the history.
- **`site.yml`** (daily + on `repository_dispatch`) rebuilds the Sapper SPA via `@upptime/status-page`, runs `.github/brand-patch.sh`, and publishes `site/status-page/__sapper__/export/` to the `gh-pages` branch. Cloudflare Pages serves `gh-pages` at `status.payhub.ly`.
- **`setup.yml`** runs on every push that touches `.upptimerc.yml` and regenerates all the other workflow files in `.github/workflows/`.

The `api/<slug>/` directories are JSON shields-style badge endpoints that Upptime maintains automatically — don't hand-edit them.

## The brand patch — read this before touching styling

`@upptime/status-page` is a published Sapper SPA. It has no in-repo source and **no theme hook**: nothing from this repo reaches the build except `.upptimerc.yml`. To brand it we patch the *generated export tree* after `command: "site"` runs:

- `.github/brand-patch.sh` overwrites icons + `global.css` inside `site/status-page/__sapper__/export/` and injects favicon `<link>` tags into the rendered `index.html`.
- It is invoked from **both** `setup.yml` and `site.yml` so that both the push-triggered rebuild and the daily cron rebuild stay branded.
- The favicon injection is guarded by a substring check; everything else is idempotent overwrite.

If you change `global.css`, the colors/fonts at the top of that file, or any icon PNG in the repo root, the change only takes effect after the next `site.yml` run (or a manual `workflow_dispatch`). It does **not** affect the next 5-minute probe commit.

## The "do not edit this file directly" warning is real

Every file under `.github/workflows/` has a banner saying it is regenerated. That regeneration happens in `setup.yml` via `command: "update-template"`. Two exceptions that survive regeneration because they're inside our own steps:

- The `Apply PayHub brand` step in `setup.yml` and `site.yml`.
- Any non-workflow change (the brand script itself, `.upptimerc.yml`, assets).

If you need to edit a workflow durably, edit the upstream template assumption (usually: add it to `.upptimerc.yml`) — or accept that direct edits will be overwritten on the next setup run.

## Common operations

- **Add a probe:** add an entry under `sites:` in `.upptimerc.yml` and open a PR. `setup.yml` runs on merge and wires the rest.
- **Investigate a red probe:** check the Issues tab — Upptime opens one per failing probe with the response body and timing.
- **Force a site rebuild without changing config:** `gh workflow run "Static Site CI"` (or use the Actions UI). Same for `Uptime CI` to force a probe.
- **Preview brand changes locally:** there is no local preview — Upptime's site generator runs inside its Action. The fastest loop is to push to a branch and trigger `site.yml` via `workflow_dispatch`.

## Conventions

- Probe-history commits use `[skip ci]` and emoji prefixes (🟩 up, 🟥 down, 📝 update). Don't filter these out when reading `git log` — they are the bulk of history but they are how this repo works, not noise.
- The default branch is `main`; the published site lives on `gh-pages` and is force-managed by `peaceiris/actions-gh-pages` — never push to `gh-pages` by hand.
